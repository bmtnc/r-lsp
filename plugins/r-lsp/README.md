# r-lsp

R language server for Claude Code, with renv support, tidyverse-aware diagnostics and a column-name check.

Gives Claude diagnostics after each edit, hover documentation, go-to-definition, find-references, workspace symbol search and call hierarchy for `.R`, `.Rmd` and `.qmd` files, across a package's `R/`, its tests, its scripts and its vignettes (all loaded at startup), plus `r-colcheck`, which checks the column names in tidyverse code against the data the code reads (local files, or a schema cache for S3 and loader data), `r-callmap`, which prints the project's whole call map at once and what a diff touches, and `r-colmap`, the same for data sources and their columns. Every change to an R file is checked, whether made through Edit, Write, a Bash command or a subagent.

## Prerequisites

- R installed, with `R` and `Rscript` on the `PATH` of the shell you start Claude Code from.
- The [`languageserver`](https://github.com/REditorSupport/languageserver) R package installed globally:

```bash
Rscript --vanilla -e 'install.packages("languageserver", repos = "https://cloud.r-project.org")'
```

This also installs [`lintr`](https://github.com/r-lib/lintr), which produces the diagnostics. If diagnostics report `.onLoad failed in loadNamespace() for 'lintr'` naming a missing package (e.g. `there is no package called 'lazyeval'`), a transitive dependency is absent from your global library — install the named package the same way.

Plugin language servers run in terminal and desktop sessions, not in Claude Code cloud sessions.

## Installation

```
/plugin install r-lsp --marketplace bmtnc/r-lsp
```

Or in two steps on Claude Code versions before 2.1.275:

```
/plugin marketplace add bmtnc/r-lsp
/plugin install r-lsp
```

Then restart Claude Code or run `/reload-plugins`.

## Verify

Start a session in an R project. The first context lines should read `R LSP plugin: R package '...'` (or `R scripts project`) with file counts and the index cache state. Ask Claude to introduce and fix a small error in an `.R` file: the server starts on that first edit (or on the first LSP call) and the conversation shows `Found N new diagnostic issues`. `r-lsp-status` prints the current server's index events. If something is missing, run `/plugin` and open the **Errors** tab.

## What Claude gets

- **Diagnostics after each change**: syntax errors, undefined functions (anywhere) and undefined variables (inside function bodies), non-exported `pkg::fun`, missing packages, deprecated, superseded or experimental tidyverse functions, functions missing from the version renv pins. After an `Edit` or `Write` in the main conversation they come from the language server. In projects without a `.lintr` file the plugin's profile (`lintr/agent_linters.R`) is used: likely bugs only, no style, and bare column names inside dplyr/tidyr/ggplot2 calls are not reported. In projects with one, that file's rules are the server's diagnostics, and the plugin's bug linters run from the post-edit hook instead; the session-start context says which case applies. For a file the server will not report on, the hook's note carries the bug linters whatever the config: a file changed through a Bash command (a heredoc, `sed -i`, `styler`, `roxygenise()`, `git checkout`; up to ten per command, the rest listed as unchecked), or edited inside a subagent, whose diagnostics never reach it. A ledger keeps a file from being checked twice, and at the end of a turn (`Stop`, `SubagentStop`) a file changed in the session that no check has seen is checked, the turn held once when there are findings. Set `R_LSP_AGENT_LINTERS=false` to use lintr's defaults.
- **A monitor only where it matters**: the index monitor (the "1 monitor" line) starts only in a directory with R code; elsewhere it exits at once.
- **Navigation that is complete when it arrives**: references, definitions, hover, document and workspace symbols and call hierarchy wait for the index (up to 30 s on first use, `R_LSP_INDEX_WAIT`) and cover every `.R`, `.Rmd` and `.qmd` file in the project. After a references, incoming-calls or definition result a note lists the mentions `grep` finds that the answer did not (roxygen links, Rmd/qmd prose, calls through `map()`/`do.call()`, the other branches of a script variable assigned inside `if`/`else`) and points out names that are data-frame columns rather than variables; after any result it says if the index is still building.
- **Column-name and argument checks**: after each `.R` edit, `r-colcheck` reads only the headers of the data files the code reads and reports column names that cannot exist at that point of the pipeline, following frames through the project's own functions (same file, `source()`d files, a package's `R/`) and through installed package functions whose output can be read from their code (a team's own cleaning functions over a database or API), and both pipes. It also reports calls to the project's own functions with an argument name the definition does not have, one R would partial-match silently, or too many arguments. Also runnable by name: `r-colcheck path/to/file.R` (exit 1 on findings; a summary of steps checked and skipped on stderr). Data it cannot open (S3 objects, databases, project loaders) is checked through a schema cache, `.colcheck/schemas.json`, keyed by the string the code passes to its loader: `r-colcheck learn KEY 'EXPR' [--source FILE.R]` evaluates the loader once in the project and records the column names; the post-edit note says which frames still need it. A cache hit is taken before a function's code is read, for piped and direct calls; `# cols: KEY` names the expression the line assigns, an entry keyed on a function name (`learn "pkg::fn"`) covers every call to a helper with a fixed output, and one keyed on a call (`learn 'fn(type = "monthly")'`) covers the calls carrying that argument. `mutate(across(cols, f))` keeps the column set; a step that loses it is named in a note, also when it sits inside a project helper the checker followed. `--steps` lists the column set after every pipeline step. A column assertion (`stopifnot(all(cols %in% names(df)))`, checkmate, or a team validator named in `.colcheck.json`) states what a frame has from that line on: checked on a known frame, the frame's columns on an unknown one. `learn --load-all` loads the package at the root with pkgload so the expression sees its functions and imports. `bind_rows()`, `rbind()` and `list_rbind()` give the union of their inputs' columns, partly known when one input is unknown. Tidyselect helpers (`starts_with()`, `contains()`, `matches()`, ...) are expanded against the known columns in every selection, and a function passed as a value inside an expression (`slide_dbl(x, sd)`) is not taken for a column. The summary leads with coverage (`12 of 15 pipeline step(s) checked`), and `--help` or a bad argument prints usage. `r-colcheck refresh [--stale] [KEY ...]` re-runs the cached expressions with the flags they were learned with. `r-colcheck discover` lists every source in the project the checker cannot open, where it is used and the command to learn it, with the cached entries and their age; `r-colcheck learn --all [--dry-run]` learns them in one run. A parquet or arrow dataset on a bucket is learned from its footer (`arrow::open_dataset(uri)`, no rows). A `loaders` entry in `.colcheck.json` describes a team's own loader (which argument is the key, what cheap expression returns the schema for `KEY`), so each key it is called with is matched, suggested and discovered the same way; `schema_ttl_days` sets when an entry is stale. `split()` or `group_split()` then `map()`/`imap()`/`lapply()`/`map_dfr()` is followed, the lambda checked with its parameter bound to the frame; `all_of(cols)` resolves when the vector is one the code states. A file that does not parse is reported with the parser's line and message. A failure of the checker itself is reported on the statement it dropped, never swallowed. The cache is gitignored by default (its own `.gitignore`) and committable by deleting that file.
- **A call map in one listing**: `r-callmap` prints every function in the project with its file:line and arguments, the project functions it calls and what calls it (functions, tests, scripts, the chunks of Rmd/qmd files), then the entry points, the functions nobody calls and any recursion. `r-callmap NAME` shows one function's callers and callees two levels each way with each call site; `--file PATH` does it for every function in a file. `r-callmap --diff [REF]` lists what the working tree changes against `HEAD` or `REF`: the definitions touched (new, arguments changed, body changed) with their callers, the definitions removed and where they are still mentioned, the top-level code changed, and the test files that reach the changed definitions with the command to run each; `r-callmap --tests NAME` gives that last part for any function. Functions passed as values (`map(x, f)`) and by name (`do.call("f")`) are edges, tagged as such. The LSP tool gives the call hierarchy one function at a time; this lets Claude plan a refactor from one listing and open only the files it names. It parses the code without running it, so calls built from strings at runtime, S4 dispatch, R6 calls through an object and inline code in Rmd/qmd prose are not in it (chunks are read, each as knitr runs it). `--json` for the same data as JSON.
- **A data map**: `r-colmap` prints every data source the code reads with its columns and where each column is used, dropped or created (file:line and verb), the columns no code uses and the columns the code creates that nothing reads; `r-colmap COLUMN` lists every site touching one column. Built on the column checker's tracking, with its limits.
- **Context at session start, and at a subagent's start**: the project's shape and whether the index cache is warm (the cache is built in the background); after `/compact` the context is printed again. A subagent is also told that the hooks' notes are its diagnostics.
- **Index events**: "index ready", "added workspace" and a too-old languageserver reach Claude through a plugin monitor, two or three lines in a typical session; `r-lsp-status` prints the full log on demand.
- **`r-lint FILE...`**: the bug profile on any file from the shell, the same code path as the hooks' note, for a subagent, a file changed through Bash, or a CI step; exits 1 with findings.
- **Skills**: `r-lsp` tells Claude when to use the LSP tool, what each answer covers, and how to get real column names for data the code does not read from a file; `r-refactor`, `r-review` and `r-data` give the order of operations for a refactor, a review of a change, and code against data that is not local.

## Working across multiple repositories

Claude Code runs one R language server per session, rooted at the directory you launched the session in. When Claude opens a file from another repository (or a directory added with `/add-dir`), the plugin adds that repository's root as a second workspace, indexes it and attaches its renv library, so definition, references and call hierarchy work there too.

Subagents share the one server and can use the LSP tool. Pushed diagnostics reach only the main conversation; the plugin's hooks run inside subagents too, so a subagent gets the column, argument and parse checks and the bug linters in the note after each of its edits, and the project context at its start. Before answering a request, the server re-reads the files it loaded that changed on disk since (a `git checkout`, `styler`, a heredoc), so its answers stay current; new files are found when something opens them. Lowercase `.r` and `.rmd` files are routed to the server like `.R` and `.Rmd`.

A large package costs memory in the server (about 1 GB for 100 R files). If you work in several large packages at once, one session per repository keeps that in check.

## Environment variables

Set in the shell that starts Claude Code: `R_LSP_AGENT_LINTERS=false` (lintr defaults instead of the profile), `R_LSP_INDEX_WAIT=<seconds>` (how long cross-file answers wait for indexing, default 30), `R_LSP_STATUS_FILE=<path>` (where index events are written; default `<plugin data dir>/status.log`), `R_LSP_HOOK_MAX_FILES=<n>` (how many R files one Bash command's hook checks, default 10), `R_LSP_REFRESH_MAX=<n>` (the most files changed on disk the server re-reads before a request, default 200), `R_LSP_LOAD_MAX=<n>` (how many test, script and Rmd/qmd files the server loads at startup, default 600), `R_LSP_COLCHECK_PACKAGES=false` (do not read installed package functions' bodies in `r-colcheck`), `R_LSP_COLCHECK_DEBUG=1` (the checker's call stack on stderr when it gives up on a statement).

See the repository README for how the pieces work, known limitations and troubleshooting.
